# VSM Harness Index

VSM Harness Index is the evidence-backed corpus of real agent-harness assessments in the OpenSiro VSM ecosystem.

## I'm human

- **Web overview:** [opensiro.com](https://opensiro.com)
- **Repository statistics:** [Corpus metrics](METRICS.md)
- **How do I contribute?** [Contribute to OpenSiro with AI](https://github.com/opensiro/vsm-oss-organization/blob/main/CONTRIBUTE_WITH_AI.md)

You can browse assessments, corpus views, and provenance directly without first learning the OpenSiro control structure. The contribution guide gives you a copy-paste route for handing an idea, issue, or open-ended contribution to an AI agent.

## I'm AI

Treat this README as the public handoff surface, then continue with the current shared [`START_HERE.md`](https://github.com/opensiro/vsm-oss-organization/blob/main/START_HERE.md). For already tracked work use the shared [`TODO.md`](https://github.com/opensiro/vsm-oss-organization/blob/main/TODO.md); for new, unclassified, cross-repository, or authority-sensitive work use [`CONTRIBUTOR_START.md`](https://github.com/opensiro/vsm-oss-organization/blob/main/CONTRIBUTOR_START.md).

If the bootstrap resolves Index work to this repository, repository-local assessment instances, accepted corpus state, provenance, reassessment bookkeeping, generated views, validation, and admission remain authoritative here.

The ownership chain is intentionally split:

```text
vsm-harness-profile
    organizational semantics
        ↓
vsm-harness-skills
    assessment + classification + synthesis Methodology
        ↓
vsm-harness-index
    accepted corpus + provenance + generated views
```

The Index does **not** define VSM functions, publication-state semantics, or the assessment artifact format.

- [VSM Harness Profile](https://github.com/opensiro/vsm-harness-profile/blob/main/PROFILE.md) is authoritative for VSM semantics.
- [`assess-vsm-harness`](https://github.com/opensiro/vsm-harness-skills/tree/main/skills/assess-vsm-harness) is authoritative for standalone assessment procedure, format, and classification.
- [`vsm-harness-skills/SYNTHESIS.md`](https://github.com/opensiro/vsm-harness-skills/blob/main/SYNTHESIS.md) is authoritative for cohort-relative synthesis and deterministic ranking projection.
- [`docs/general-assessment.md`](docs/general-assessment.md) defines this repository's general-assessment scope and its boundary with future domain-specific indexes.
- [`INDEXING.md`](INDEXING.md) defines Index-local intake, provenance, reassessment bookkeeping, and publication/materialization rules; [`docs/assessment-lifecycle.md`](docs/assessment-lifecycle.md) owns the publication lifecycle.

The primary artifact flow is:

```text
repository @ pinned revision
        ↓
assessment produced under Profile + Methodology
        ↓
assessments/<harness_id>.md
        ↓
        ├── cohort synthesis → data/signatures.psv → TLDR.md
        └── deterministic projection → RANKINGS.md / derived views
```

`data/catalog.psv` is deliberately separate. It is discovery/order/provenance infrastructure and contains no VSM classifications.

## Assessments

`assessments/<harness_id>.md` contains accepted repository-relative findings at a pinned revision.

Adding another harness must not change an existing assessment merely because the comparison cohort changed.

The assessment body, required evidence fields, allowed publication notation, negative-state requirements, parent-mode rules, and function-specific decision tests are all owned by the active `vsm-harness-skills` Methodology rather than repeated here.

CI checks out the version-pinned active Skills release and runs its structural assessment contract checker before accepting active-version artifacts.

## Signatures

`data/signatures.psv` contains cohort-relative signatures generated by applying the Skills synthesis procedure to accepted standalone assessments in stable catalog order.

A signature may change when an earlier comparison item is admitted or corrected. It must never rewrite the underlying standalone assessment merely to make the row distinct.

`TLDR.md` is the materialized public view of those signatures.

## Rankings and derived views

`RANKINGS.md`, `FULL_A.md`, metrics, and analytics are deterministic materializations from canonical Index data under the active Methodology projection rules.

They are not independent assessment layers and they do not own publication-state meaning.

The rendering code in this repository is a **consumer implementation** of `vsm-harness-skills/SYNTHESIS.md`. A future Methodology change may require an explicit consumer-compatibility update here before the new contract is activated or migrated through the corpus.

## Corrections and reassessments

Open an `[Assessment re-review]` issue when stronger primary evidence may change an accepted assessment or when a newer upstream revision materially changes the reviewed harness.

Index bookkeeping distinguishes:

- **same-ref correction / semantic revalidation** — the accepted `review_ref` remains fixed;
- **new-ref reassessment** — a newer upstream commit becomes the accepted review boundary.

How the repository is semantically reassessed comes from the applicable Skills Methodology. How the accepted boundary, freshness, history, signatures, and generated views are recorded is Index-local.

See [CONTRIBUTING.md](CONTRIBUTING.md), [INDEXING.md](INDEXING.md), and `reassessments/`.

## Continuous index

New candidates follow:

```text
discover → deduplicate → queue → pin → assess → admit → synthesize → regenerate → validate → reassess
```

`data/catalog.psv` owns discovery/order/provenance; `assessments/` stores accepted repository-relative research artifacts; `data/signatures.psv` stores cohort-relative synthesis results; generated Markdown and analytics are materialized views.

## Contributing

Use this repository for harness discovery/intake, assessment instances, reassessment history, catalog/provenance maintenance, signatures, generated Index views, and Index-local tooling. See [`CONTRIBUTING.md`](CONTRIBUTING.md) for the actionable workflow and [`INDEXING.md`](INDEXING.md) for Index-owned lifecycle and provenance rules.

Changes to assessment format, classification procedure, publication states, synthesis semantics, or ranking projection belong in `vsm-harness-skills`; changes to VSM semantics belong in `vsm-harness-profile`. The shared entry routes at the top of this README own current-work and cross-repository routing.
