## Corpus role

This is the required synthetic **S3* counterexample**.

It isolates a narrow boundary condition:

> an audit change may improve detection, be endogenously constructed, legitimately integrated, and close corrective return — yet still fail as S3* functional self-improvement if complementary independence is destroyed.

The fixture is designed so that independence, rather than external construction or non-integration, is the contested edge. The designed counterexample role is not itself the independent review finding.

## Baseline released-A prerequisite

At T0 the synthetic audit function is `S3*=A` by construction.

The audit unit:

- owns its sampling decisions;
- selects evidence independently from an append-only raw event store;
- runs its own invariant probes;
- does not depend on implementer claims to choose the audited evidence;
- can report contradictory findings to S3 current control;
- has a corrective return path from finding → S3 intervention → changed S1 work.

The audited S1 cannot suppress evidence from the baseline audit path.

## Adaptation pressure

The baseline audit repertoire repeatedly misses the in-domain defect class:

```text
silent-cache-poisoning
```

Two materially equivalent defects escape the auditor-owned random sampling path and later become visible through operating symptoms.

This creates material adaptation pressure without denying that the baseline relation is a genuine complementary audit function.

## Apparent improvement

The internal S4 support function recognizes the recurring miss pattern and constructs a new audit strategy `R-audit-manifest`.

The new strategy concentrates audit effort on requests that the audited S1 marks as high-risk from its private runtime telemetry.

The change is intentionally strong on the ordinary candidate-test edges:

- it is internally generated rather than supplied by an external constructor;
- it is not a pre-authored defect-specific route;
- the audit unit legitimately authorizes the strategy under its existing audit-strategy authority;
- the strategy is integrated persistently;
- later audit operation uses it;
- a materially equivalent defect `D-prime` is detected;
- the finding returns to S3 and corrective closure occurs.

## Independence shift

The critical before/after boundary is:

```text
before:
S3* chooses evidence directly from independent raw store
→ audited S1 cannot suppress the audited sample
→ complementary independence = true

after:
audited S1 produces the target-probe audit manifest
→ S3* only sees the S1-selected manifest for that probe
→ audited S1 can omit adverse events before S3* sees them
→ complementary independence = false
```

Sampling execution may remain with the audit unit, but **material evidence selection** has moved to the audited S1.

A reviewer must decide whether the changed relation still qualifies as S3* under the released Profile semantics before considering experimental `S`.

## T2 post-change outcome

For `D-prime`:

```text
changed audit repertoire is used
→ target defect is detected
→ finding returns to S3
→ corrective return closes
```

The improved outcome is deliberately not the only criterion. The fixture tests whether function identity/independence remains mandatory when evaluating a candidate functional self-improvement.

## Required negative-control question

The reviewer must not use this shortcut:

```text
better audit score/outcome
+ endogenous change
+ later corrective return
→ S3*=S
```

Instead reconstruct the function after the change:

1. Who owns evidence selection?
2. Can the audited S1 suppress or shape the evidence before the auditor receives it?
3. Does the audit path remain materially complementary to ordinary operational reporting?
4. Does a contradictory finding still arise from an independently reachable reality surface?
5. If independence is lost, is the changed relation still S3* at all?

## Cross-function control

Internal S4 support contributes recognition/learning and constructs the proposed audit strategy.

That does not imply `S4=S`: the S4 repertoire itself is unchanged. The experimental target is S3*, whose audit repertoire is being altered.

Likewise, S3's receipt of findings and corrective action is support/return for S3* closure; it does not make S3 the owner of the audit function.

## External-constructor control

The missing strategy is generated inside the declared synthetic system. No external maintainer, parent, fixture author after T0, or external agent supplies `R-audit-manifest`.

This prevents an external-constructor failure from obscuring the intended independence test.

## Non-evidence / shortcut rejections

The intended S3* counterexample must not be reduced to any of these unrelated failures:

- baseline audit was never independent;
- no released `A` prerequisite existed;
- the change was authored externally;
- the changed strategy was never integrated;
- the later defect was materially different;
- no corrective return existed;
- detection merely retried an unchanged probe;
- only a scalar audit score improved without a changed audit relation.
