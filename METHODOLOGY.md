# Indexing policy

`vsm-harness-index` does not maintain a second VSM methodology. It applies:

1. `vsm-harness-profile/PROFILE.md` for the meaning of organizational functions;
2. `vsm-skills/skills/assess-vsm-harness` for evidence collection, scoring, confidence, TL;DR, and assessment artifacts;
3. this document only for index-specific publication rules.

## Entry boundary

Each entry assesses a named harness at a pinned tag or commit where possible. Framework affordances, a deployed application, and the vendor organization are different systems-in-focus and must not be mixed.

The index uses an agent-autonomy lens: it asks which autonomous agent absorbs
variety and holds each VSM decision right. Deterministic framework mechanisms and
human gates are supporting infrastructure, not autonomous enactment by themselves.

The index publishes three distinct frames:

1. **Observed current** for evidenced structure and recurring operation at a pinned snapshot.
2. **Structural affordance** for framework mechanisms that support, partly enable, prevent, or leave a VSM function unverified.
3. **Target projection** for a named hypothetical system and proposed configuration.

Only observed current and a scenario-bound target projection may carry numeric scores. The main comparison table is a structural-affordance map and has no aggregate score.

## Discovery cohort

The compact TL;DR catalog and detailed assessments are separate layers. The catalog
may use a curated secondary source to discover candidates and form a reproducible
review queue. Its TL;DR text is provisional VSM interpretation, not a substitute for
the primary-source evidence required by a detailed assessment.

The current cohort is adapted from the pinned source documented in
[`SOURCES.md`](SOURCES.md). It retains loop-owning, non-evaluation projects and sorts
them by GitHub repository creation timestamp, with repository name as the tie-breaker.
That timestamp is a reproducible ordering proxy; it is not the date when autonomous
functionality first appeared. Local additions must identify their provenance and join
the same sort before positions are regenerated.

## TL;DR review order and evidence

Review catalog candidates by ascending `catalog_position`, beginning at position 1. Record the pinned `review_ref` and `reviewed_at` boundary before assigning categorical autonomy states. After the forward pass, compare each fingerprint with all later positions and retain the most informative evidenced distinction. Display order may remain newest-first; it does not change review order.

`tldr_status: excluded-no-agentic-vsm` records candidates whose standard documented setup does not establish an autonomous decision/action loop. A documented core runtime dependency may carry that loop; an optional third-party plugin or merely compatible API may not. Excluded candidates remain in the discovery catalog but are not rendered as fingerprints.

## Published statuses

| Status | Index meaning |
| --- | --- |
| `+` | Direct evidence establishes that an autonomous agent can exercise the relationship with bounded decision rights. |
| `+-` | A material mechanism exists, but agent ownership, authority, or relationships remain application-dependent. |
| `-` | Direct evidence establishes absence or explicit exclusion; use sparingly. |
| `?` | The evidence set cannot establish presence or absence. |

Every `+` and `+-` requires a primary source. Missing documentation remains `?`. Internal assessment artifacts may retain descriptive enum values such as `unknown`; the symbols are the human-facing index notation.

## Data ownership

- `data/catalog.psv` stores the source-derived discovery cohort, chronology, and
  provisional VSM TL;DR;
- `data/assessments/**/*.json` stores detailed skill output and evidence.
- `data/harnesses.csv` and `data/harness-metrics.csv` are deterministic projections generated by the assessment skill's `upsert_harness.py`.
- `entries/*.md` explains the qualitative mapping and uncertainty.
- `TLDR.md` renders the complete catalog newest-first, with detailed assessments
  overriding provisional TL;DR text by `harness_id`;
- the structural table contains only completed detailed assessments.

The internal JSON layout and scores support this repository only. They are not harness manifests, VSM standards, or benchmark leaderboards.

## Review rule

A contribution must run the same assessment skill version across harnesses it compares, retain raw sub-scores, identify evidence coverage, and avoid comparing unavailable values as zeros. Longitudinal comparisons must also pin reviewed refs and rubric versions.

Current projections require rubric `vsm-assessment/v2`. Structural-affordance artifacts contribute to the TL;DR projection; only observed-current or target-projection metrics contribute to the score table.
