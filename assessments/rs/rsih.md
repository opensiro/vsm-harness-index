## Repository architecture

RSIH packages Pi coding-agent `0.84.3` as its runtime core and places a first-party Genome adapter around it. `src/pi-cli-runtime.ts` resolves a selected Genome, projects its model/runtime/resource/settings choices into Pi, adds generated/MCP resources, preserves/resumes the selected Genome in session state, and then invokes Pi's standard `main`. Without a Genome, the documented and tested invariant is that `rsih` behaves like Pi except for the RSIH configuration directory.

A Genome is an inherit-by-default configuration bundle. It can alter or append the system prompt, tool availability/schema, skills, prompt commands, provider/model settings, runtime behavior, policies/memory/compaction, MCP/extensions, appearance, settings/keybindings, and resource discovery. First-party validation constrains each component to its contract; runtime projection turns accepted fields into Pi CLI arguments, managed settings/keybindings and extension-time behavior.

The interactive `supervisor.ts` is process-lifecycle machinery for complete Genome switches, not an organizational manager. It runs one real agent child, watches for a user-requested Genome switch, restarts the same persisted session under the new configuration, and rate-limits restart loops. Non-interactive modes are not supervised this way.

The shipped `harness-rsi` Genome, launched directly or through `gee`, is an evidence-driven constructor. It asks what a future Genome is for, scans user-selected historical session stores, has the model analyze patterns against the stated future scenario, develops concrete component proposals, requires the user to approve the complete plan before any file is written, then writes and validates a self-contained Genome bundle. That bundle can later be loaded by the ordinary RSIH Genome path. Under the Index boundary rule, however, that materialized specialization is a separate system-in-focus; its later operating closure is not credited back to the base constructor.

## Operational model

The ordinary RSIH operational unit is one model-driven Pi agent session assembled by RSIH. The model chooses substantive coding/tool actions and receives tool/environment results through the Pi execution loop; RSIH supplies the selected Genome's persistent configuration and runtime projection around that loop.

The `harness-rsi` mode is not treated as a second concurrent S1 in the same organization. It is an alternative first-party mode whose operational task is constructing a future Genome. Its output is a persistent configuration artifact. Once that artifact is selected as an operating specialization, it becomes a separate system-in-focus rather than another S1 inside the base RSIH organization.

## Recursion

RSIH can create and load multiple Genomes, but configuration plurality is not automatically VSM recursion. The base distribution is the system assessed here. A generated Genome materially specializes purpose, prompts, capabilities and policy and is therefore treated as a separate system-in-focus for later evidence, not as a recursive child whose autonomy can be assumed from the constructor.

## Variety and escalation

RSIH attenuates operational variety through Pi tool/runtime mechanics, Genome contracts/schema validation, inherit-by-default configuration, explicit resource isolation, max-turn/runtime settings and persistent sessions. GEE reduces adaptation-design variety by aggregating historical evidence before selective transcript reading, requiring evidence for persistent changes and escalating ambiguous evidence/intent conflicts to the human. The mandatory whole-Genome approval is treated as constructor governance, not as S3 or as base S5 closure.
