## Repository architecture

The source publishes a substantive deterministic governance/runtime architecture, not merely a prompt collection. §TemplateBoundTaskInterpreter§ and formation compile bounded domain tasks. Native TeamHarness lifecycle adapters can create/assign/acknowledge/submit/check tasks with controlled-local Matrix transport, process isolation and provenance. The four Product/Legal/Finance/GTM workers in the named native reference are explicitly deterministic; a separate reviewer can make one structured model call. An optional Vertex-backed OAC agent produces mapping candidates through a pinned AgentTeams handoff, but §validate_oac_agent_candidate§ requires exact source/target bindings and forbids authority expansion or effect rights. The control plane then checks dependencies/impact, obtains human owner approval tied to a digest/version and only permits an authorized executor to Apply.

The Quote and Discount Memo handlers remain fixed typed rendering paths; optional model answers never write business truth directly. Replanning and recovery preserve bounded context and receipts but the named owner/requester/executor controls return-for-evidence, resumption and application. Source docs explicitly limit validation to controlled-local reference cases and distinguish model calls, Matrix simulation and distributed deployment. References: [architecture](https://github.com/bingjiezhu/OrgRebase/blob/ef0785041b68bef13b4f5e0227c0e6d5f969046f/orgrebase/docs/guide/architecture.en.md), [approach](https://github.com/bingjiezhu/OrgRebase/blob/ef0785041b68bef13b4f5e0227c0e6d5f969046f/orgrebase/docs/guide/approach.en.md), [agentteams](https://github.com/bingjiezhu/OrgRebase/blob/ef0785041b68bef13b4f5e0227c0e6d5f969046f/orgrebase/docs/guide/agentteams.en.md), [model-assisted demo](https://github.com/bingjiezhu/OrgRebase/blob/ef0785041b68bef13b4f5e0227c0e6d5f969046f/orgrebase/docs/guide/demo.en.md), [mapper](https://github.com/bingjiezhu/OrgRebase/blob/ef0785041b68bef13b4f5e0227c0e6d5f969046f/orgrebase/src/orgrebase/workspace/oac_agent_adaptation.py), [competition subprocesses](https://github.com/bingjiezhu/OrgRebase/blob/ef0785041b68bef13b4f5e0227c0e6d5f969046f/orgrebase/src/orgrebase/workspace/competition_worker.py).

**Counterfactual owner test:** remove model providers and externally configured agent/reviewer calls, leaving OrgRebase's shipped control plane and reference configuration. The model-free Quote workflow still produces a business output, validates impact and enforces exact owner/executor choices. The remaining system does not itself gain model-owned local task judgment, action selection and feedback recovery. Conversely, keeping the model call but removing human owners leaves bounded candidate advice and no canonical business Apply. Neither support path alone transfers ownership of an autonomous operational S1 to OrgRebase.

## Operational model

Structured admitted source / task → deterministic planning, four domain candidate programs and optional constrained mapping/reviewer model call → typed candidate/Quote and independent checks → requester or named owner review → exact approval → authorized Apply → successor object and receipts. Model reviewers and mappers can affect candidate content; they cannot admit themselves or close the regulated enterprise change. Distinguish third-party model computation from first-party orchestration, and artifact-level human business authority from organizational S3/S5 of an autonomous agent harness.

## Distributed OSS parent arrangement

The public repository publishes an enterprise Pack and documented user-role authority, but not a shared autonomous first-party OSS agent organization whose independently operated agent cells are governed by GitHub maintainers. Demo role sessions are simulations, not independent institutional authority. Do not infer organization-level parent modes from repository maintainers or synthetic domain owners.

## Self-hosted and non-human modes

A local operator may select a model provider or remain model-free; configured HTTP inference is a bounded dependency rather than autonomous governance. The optional human-owned source/Quote approval path is functionally important but does not itself prove S3/S4/S5 of an agent system. There is no declared fully non-human ultimate authority in the reviewed supported reference.

## Recursion

The Product/Legal/Finance/GTM role labels and native TeamHarness tasks are task decomposition. Each deterministic role has a bounded context and work result, but no evidenced locally self-regulating viable operational subsystem with independent recursive metasystem.

## Variety and escalation

Source gaps, unknown impact, stale versions and missing evidence are attenuated by source binding, fail-closed gating, owner approval and typed recovery. These are real controls, not automatically agent-owned organizational regulation. Exceptional failure may return to the requester/owner, not an independently evidenced algedonic path.
