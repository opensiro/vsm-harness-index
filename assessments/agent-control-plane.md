## Repository architecture

The repository makes the boundary explicit. README states that the control plane decides when/how an agent may act while the data plane executes side effects. The architecture document says the package separates decision governance from execution, is intended to be embedded into application runtimes, and does not replace the execution framework itself. Its reference sequence ends with the application handing an allowed action to an external `Execution Plane`.

The library nevertheless contains substantial current-control support: deterministic risk classification/routing, approvals, budget guards, scoped kill switches, concurrency controls, precondition verification, session risk accumulation, event persistence, recovery and steering. `RuntimeMonitor` can request cancellation when risk escalates mid-execution, but the architecture explicitly calls the path cooperative: ACP signals while the host executor decides what cancellation means.

`McpGateway` preserves the same ownership line. Its `ToolExecutor` protocol is documented as a "Host-provided tool execution backend" and the gateway constructor requires such an executor. ACP can govern and invoke that seam, screen tool output and record the result, but it does not provide the autonomous reasoning loop that decided to issue the tool call or the execution backend that performs the substantive side effect.

The continuous-operation examples do not change the standard boundary. The long-running example is a deterministic workload/governance simulation whose cases and approve/deny decisions are generated by Python rules. The OpenAI Agents SDK integration explicitly imports `Agent` and `Runner` from the optional external `openai-agents` package and feeds that external model decision into ACP. These are integration demonstrations of an embedded governance library, not first-party agent execution ownership.

Counterfactual owner test: remove the host application/agent SDK/tool executor while leaving ACP policy, routing, approval, budget, risk, event, recovery, gateway and runtime-monitor machinery intact. The first-party package can classify hypothetical proposals, preserve state, enforce configured constraints and signal interventions, but it cannot receive an objective and autonomously choose and execute the substantive model/tool actions needed to accomplish it. Operational S1 closes outside the assessed repository boundary.

Under Methodology `0.3.6`, strong governance around adjacent autonomous agents does not establish first-party S1. The proposed terminal outcome is therefore `excluded-no-agentic-vsm`, not an included constructor vector composed from governance primitives.

## S1 — Operations

- State: —
- Function: no first-party autonomous operational decision/action loop is established inside the ACP library boundary.
- Disturbance / variety regulated: ACP regulates proposal risk, permissions, budgets, approvals, session state and intervention conditions; substantive task uncertainty and action selection are handled by the embedding agent/application.
- Decisive decision or feedback right: interpret the user/system objective, choose the next substantive model/tool action, execute it and use its result to select subsequent work.
- Decision owner: host autonomous agent/runtime and host-provided executor, not a first-party ACP autonomous actor.
- Supporting / enforcement mechanisms: policy engine, proposal router, approvals, budgets, kill switch, preconditions, event store, recovery, runtime monitor and MCP gateway.
- Closure path: host agent proposes action → ACP classifies/gates/signals → host executor performs permitted action → result/events return → host agent/runtime decides what substantive action follows.

## Proposed terminal outcome

`excluded-no-agentic-vsm`.

Agent Control Plane is a substantive governance framework for autonomous systems. The exclusion is repository-boundary-specific: its public contract intentionally leaves autonomous agent reasoning and execution to the embedding runtime, so the first-party package does not establish the operational S1 required for Index inclusion.

## Evidence boundaries / caveats

- No VSM function is inferred from names such as `control plane`, `router`, `policy engine`, `agent registry`, `evaluator`, `runtime monitor` or `recovery`.
- Deterministic governance classification and hard enforcement are separated from autonomous organizational decision ownership.
- Examples are used to clarify the integration boundary, not to import optional external SDK actors into the library.
- The host-provided `ToolExecutor` seam is treated as environmental execution ownership even though ACP calls it after governance succeeds.
- A host application + autonomous agent + ACP deployment is a different system-in-focus and may have positive S2/S3/S3*/S4/S5 classifications depending on its closure paths.
