## Operational model

In the default mode, one model-guided coder absorbs user-task uncertainty through tool/action feedback. When opted into agent teams, multiple first-party teammates can work as distinct S1s on assigned tasks. The shared task list, lock-protected claims, dependency graph and owner/status updates regulate collisions among those units; the team-lead model can retain a view of current team work and discretion to allocate or correct commitments. Generic child delegation and messages alone are not assigned S2/S3; the specific lock/conflict protocol and whole-team owner/status/decision loop provide the stronger witnesses below. Hosted/third-party reviewers and internal `USER_TYPE=ant` features are not borrowed.

## S2 — Coordination

- State: C
- Function: reduce cross-S1 contention over the same outstanding team work, while respecting prerequisite dependencies and incompatible claims.
- Disturbance / variety regulated: two operational teammates attempting to own the same work item, an agent simultaneously claiming overlapping obligations, or a successor task being picked before a blocking predecessor is complete.
- Decisive decision or feedback right: atomic admission/rejection of a task claim relative to its owner, status, blockers and agent busy state; subsequent worker selection can attempt another eligible task.
- Decision owner: first-party lock/claim protocol selects the conflict response deterministically; teammate/lead models select which task to attempt and can react to refusal, but there is insufficient evidence that an agent autonomously owns the *S2-specific* conflict regulation judgment. Thus constructor-level `C` rather than `A`.
- Supporting / enforcement mechanisms: `proper-lockfile`, on-disk task state, dependency edges, owner/status markers, task watcher, background/in-process worker and mailbox notifications.
- Closure path: two teammates examine shared work → per-list/per-task lock serializes claim → conflicting/blocked/busy claim rejected without duplicate owner, or valid claim recorded → watcher/runner receives result → worker proceeds only with admitted task or returns to next eligible-work check.
- Distinct S1 units: at least two independently executing named team teammates with assigned operational work in the opted-in team mode.
- Inter-S1 disturbance: simultaneous claims of the same task and dependency-order interference between their separate work units.
- Attenuating coordination relation: exclusive task locks and atomic owner/dependency/busy checks prevent overlapping claims; dependency graph inhibits premature successor work.
- Feedback into subsequent S1 behaviour: [src/hooks/useTaskListWatcher.ts](https://github.com/Aliivihu786/astro-code/blob/5aae2bddfc364bc492a8cae509b20eb94455560c/src/hooks/useTaskListWatcher.ts) and [src/utils/swarm/inProcessRunner.ts](https://github.com/Aliivihu786/astro-code/blob/5aae2bddfc364bc492a8cae509b20eb94455560c/src/utils/swarm/inProcessRunner.ts) use `claimTask` success/failure to determine which task prompt is executed; [src/tools/TaskListTool/TaskListTool.ts](https://github.com/Aliivihu786/astro-code/blob/5aae2bddfc364bc492a8cae509b20eb94455560c/src/tools/TaskListTool/TaskListTool.ts) reports newly available/blocked tasks; failed submission releases a claim.
- Why this is S2-specific rather than generic communication / routing / sequencing / shared state / delegation: the claim operation explicitly recognizes competing owners and pending predecessor commitments and changes which S1 may act; the relation is not inferred solely from queue or message existence.
- Boundary reachability: External users explicitly opt into a first-party team with ASTRO_CODE_EXPERIMENTAL_AGENT_TEAMS or --agent-teams; the supported team creation/AgentTool spawn path supplies actual teammates, and both useTaskListWatcher and inProcessRunner call the shipped claimTask before submitting work. The conflict check is a functional, not hypothetical, local distribution path.
- Why this is / is not agent-owned: models decide their coding work, while fixed claim and lock code supplies collision-specific rejection. No independently evidenced agent right to revise this coordination protocol was established.
- Evidence: [src/utils/tasks.ts](https://github.com/Aliivihu786/astro-code/blob/5aae2bddfc364bc492a8cae509b20eb94455560c/src/utils/tasks.ts); [src/hooks/useTaskListWatcher.ts](https://github.com/Aliivihu786/astro-code/blob/5aae2bddfc364bc492a8cae509b20eb94455560c/src/hooks/useTaskListWatcher.ts); [src/utils/swarm/inProcessRunner.ts](https://github.com/Aliivihu786/astro-code/blob/5aae2bddfc364bc492a8cae509b20eb94455560c/src/utils/swarm/inProcessRunner.ts); [src/tools/TaskListTool/TaskListTool.ts](https://github.com/Aliivihu786/astro-code/blob/5aae2bddfc364bc492a8cae509b20eb94455560c/src/tools/TaskListTool/TaskListTool.ts); [src/tools/TaskUpdateTool/TaskUpdateTool.ts](https://github.com/Aliivihu786/astro-code/blob/5aae2bddfc364bc492a8cae509b20eb94455560c/src/tools/TaskUpdateTool/TaskUpdateTool.ts); [src/utils/agentSwarmsEnabled.ts](https://github.com/Aliivihu786/astro-code/blob/5aae2bddfc364bc492a8cae509b20eb94455560c/src/utils/agentSwarmsEnabled.ts).

## S3 — Inside-and-now control

- State: A
- Function: regulate the active team as a whole through owner/commitment allocation and responses to changing team status or blockers, not just assign one task for execution.
- Disturbance / variety regulated: several active teammates with outstanding or blocked work, mismatched worker/tool capacity, idle workers, dependency bottlenecks and disputed responsibilities.
- Decisive decision or feedback right: lead model chooses team composition and current work distribution, assigns/reassigns owners, adds dependencies, follows completion/blocked status, sends corrections to peers and authorizes shutdown/handoff of workers.
- Decision owner: model-guided `team-lead` at the local team recursion. Static tools persist decisions but do not select which obligation/worker/priority should change.
- Supporting / enforcement mechanisms: `TeamCreate`, `TaskList`, `TaskUpdate`, `SendMessage`, team roster, idle/status notifications and execution/worker lifecycle.
- Whole-system current view: team roster, task list with ownership, status and `blockedBy`, team messages and idle/completion signals accessible to the lead rather than only a single worker's transcript.
- Current-control decision scope: resource/worker assignment, reassignment, dependency constraints, requests for help, peer intervention and closing down the current team when work finishes.
- Closure path: teammate result/blocked or idle signal → lead's shared current-team view and model judgment → owner/dependency/message/team roster update → next teammate claim/prompt/coding action reflects the lead's revised commitment.
- Boundary reachability: In the explicitly enabled local first-party team mode TeamCreate registers the leader and shared task list, AgentTool starts named teammates, TeamCreate prompt and TaskList present the whole active obligations, and TaskUpdate/SendMessage return lead allocations and interventions to their teammates. These are not external hosted-controller rights.
- Why this is / is not agent-owned: with the lead model removed the team file and tools can persist old assignments, but they do not autonomously select new priorities or settle which current work to reassign as the global situation changes.
- Evidence: [src/tools/TeamCreateTool/TeamCreateTool.ts](https://github.com/Aliivihu786/astro-code/blob/5aae2bddfc364bc492a8cae509b20eb94455560c/src/tools/TeamCreateTool/TeamCreateTool.ts); [src/tools/TeamCreateTool/prompt.ts](https://github.com/Aliivihu786/astro-code/blob/5aae2bddfc364bc492a8cae509b20eb94455560c/src/tools/TeamCreateTool/prompt.ts); [src/tools/TaskListTool/TaskListTool.ts](https://github.com/Aliivihu786/astro-code/blob/5aae2bddfc364bc492a8cae509b20eb94455560c/src/tools/TaskListTool/TaskListTool.ts); [src/tools/TaskUpdateTool/TaskUpdateTool.ts](https://github.com/Aliivihu786/astro-code/blob/5aae2bddfc364bc492a8cae509b20eb94455560c/src/tools/TaskUpdateTool/TaskUpdateTool.ts); [src/tools/SendMessageTool/SendMessageTool.ts](https://github.com/Aliivihu786/astro-code/blob/5aae2bddfc364bc492a8cae509b20eb94455560c/src/tools/SendMessageTool/SendMessageTool.ts); [src/tools/SendMessageTool/prompt.ts](https://github.com/Aliivihu786/astro-code/blob/5aae2bddfc364bc492a8cae509b20eb94455560c/src/tools/SendMessageTool/prompt.ts); [src/utils/swarm/teamHelpers.ts](https://github.com/Aliivihu786/astro-code/blob/5aae2bddfc364bc492a8cae509b20eb94455560c/src/utils/swarm/teamHelpers.ts); [src/utils/agentSwarmsEnabled.ts](https://github.com/Aliivihu786/astro-code/blob/5aae2bddfc364bc492a8cae509b20eb94455560c/src/utils/agentSwarmsEnabled.ts).
