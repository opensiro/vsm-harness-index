## Repository architecture

The canonical architecture note explicitly separates a deterministic single state writer from untrusted model and tool capabilities: it states that planners, executors and verifiers get snapshots but cannot commit a cursor/DAG next-state without controller checks. `matterloop_core.AgentLoop` loops planner→execute→verify and may replan, await human approval, persist checkpoints and resume with bounded cycle/attempt/token/time budgets. Its host composition root supplies planner, executor, verifier, model providers, secrets, audit publisher, checkpoint stores and resource decisions. ## Operational model

A host defines goal, acceptable plan, capabilities, tool access, resources and endpoints. A configured model planner and agent endpoints make task-contingent decisions and execute locally; deterministic controller commits result and verifier/reviewer acceptance and ensures durable sequence, resource safety, and requested escalation. At model-independent static mode the same controller remains a pure executor; the positive S1 assessment is for the supported reachable model-backed path, not for every embedding. Neither finite task team membership nor retrospective memory advisory output is silently extended to organizational executive roles.

## S1 — Operations

- State: A
- Function: Real goal-constrained planning, delegated task execution and model-guided replanning with independent verification or human review as needed.
- Disturbance / variety regulated: Uncertain task decompositions, model outputs and tool errors, verification failure, human pending decisions, context loss, retries and queue crashes.
- Decisive decision or feedback right: Planners and model agent endpoints can generate plans/task decisions and execute assigned work against available tools; structured results and verifier feedback influence another plan revision or step choice. Core AgentLoop supports a single-task and TeamOrchestrator routes model-planned capability-specific DAG work to registered endpoints.
- Decision owner: Host-chosen model-capable Planner/Executor/AgentEndpoint components and TeamReviewer/Verifier under bounded single-writer deterministic controllers. The model determines task content and steps; the controller owns state/counters/commit and host owns injection/configuration.
- Supporting / enforcement mechanisms: AgentLoop planner→executor→verifier/replan; TeamOrchestrator planner→task graph→capability-aware routing/parallel endpoints→task verification→result aggregation/review; human interaction and checkpoint/CAS; optional model implementations.
- Closure path: User request → model-injected plan/tasks → selected endpoint executes and returns result → separate verifier decision and/or TeamReviewer accept/replan → state persisted → next plan/operation or completion, pause or explicit bounded failure.

## S3 — Inside-and-now control

- State: —
- Function: No independent inside-and-now whole-organization management of multiple separately viable S1 departments, though there is genuine current **team task** supervision, checkpointing, resource limit, and model-supported replanning.
- Disturbance / variety regulated: Aggregate task-status problems, exceeded resource/cycle budgets, verifier rejection, disagreement in team draft quality, paused user decisions and failed worker leases.
- Decisive decision or feedback right: A TeamReviewer can evaluate a complete task graph's draft and choose ACCEPT, REPLAN, REQUEST_HUMAN or STOP, returning a binding result for that **single team goal**. The controller routes/plans within current-task limits but is not demonstrated as owner of cross-departmental priorities, commitments, accountable organization-wide resource allocation or synergy.
- Decision owner: Host-injected TeamReviewer/TeamPlanner (optional model), operator's request and configured deterministic TeamOrchestrator; no standing S3 department accountable for an operating portfolio distinct from task runner.

- Closure path: Current team's draft → reviewer accepts/replans/pauses/stops → task graph reissued or run state changed. This is real project-task management, but no whole-current enterprise portfolio of viable S1 departments and no owner of ongoing collective-resource commitments.
- Why this is / is not agent-owned: Model review is discretionary within **one finite deliverable**, not evidence of a standing owner for ongoing different viable S1 services; an external human approval of a task step cannot alone justify parent S3.
