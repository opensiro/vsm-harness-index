# R2R

## Review boundary
R2R at the pinned revision, focusing on its first-party agentic RAG/research-agent runtime.

## Repository architecture
R2R implements RAG/research agents that iteratively use document, content and web-search tools. Research mode also exposes a dedicated critique path that can call a specialized reasoning model over the accumulated conversation as a second opinion.

## Primary evidence
- `py/core/agent/rag.py`: RAG agents expose first-party retrieval/content/web-search tools as operational research capabilities.
- `py/core/agent/research.py`: `ResearchAgentMixin` can register a `critique` tool whose description explicitly asks for a second opinion on the current reasoning, logical flaws, biases, overlooked considerations and alternative approaches; the critique is generated by a specialized reasoning-model call over the conversation history.
- Base/research configuration keeps `critique` out of the default tool set, so the mechanism is available first-party but is not a mandatory/default closed reviewer for every run.

## Operational model
The research agent is S1. Retrieval and web search extend that S1's task-local informational variety. The optional critique path is functionally different: it re-reads the operational reasoning through a separate reasoning prompt/model and returns findings to the primary research loop.

## S1 — Operations
`A`: the agent chooses retrieval/search/reasoning tools and iterates toward research answers. Confidence: high.
