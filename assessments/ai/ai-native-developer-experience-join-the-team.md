## Repository architecture

The [plugin manifest](https://github.com/jpantsjoha/ai-native-developer-experience/blob/e93069b92735ba096abf662f2b9d95a0ebfd36f9/plugin.json) declares installable Agent Plugins v1 distribution and host extension points. [hooks/session-start](https://github.com/jpantsjoha/ai-native-developer-experience/blob/e93069b92735ba096abf662f2b9d95a0ebfd36f9/hooks/session-start) reads the `using-the-harness` skill and emits a host-compatible context pointer. [commands/bootstrap.md](https://github.com/jpantsjoha/ai-native-developer-experience/blob/e93069b92735ba096abf662f2b9d95a0ebfd36f9/commands/bootstrap.md) invokes first-party `bootstrap_operating_model.py` from the host's installed plugin root, while the validator refuses unsafe active policy assumptions. These create a concrete host invocation/entry path rather than merely sharing a general-purpose white paper.

The core first-party `get-it-done` skill contains a full goal execution contract: decompose/reprioritize actual work, branch, implement, prove tests fail meaningfully, get fresh independent candidate-bound review, integrate on the admitted Git branch and return new project status and decision records. Unlike a generic role description, the installed host uses these instructions to decide tool actions and respond to failures and reviewer verdicts. The agent is the host model *inside a first-party plugin-defined work cell*; the plugin has no independent hosted model process, background daemon, standalone API model transport or self-issued authority. [get-it-done](https://github.com/jpantsjoha/ai-native-developer-experience/blob/e93069b92735ba096abf662f2b9d95a0ebfd36f9/skills/get-it-done/SKILL.md); [delivery-orchestrator](https://github.com/jpantsjoha/ai-native-developer-experience/blob/e93069b92735ba096abf662f2b9d95a0ebfd36f9/skills/delivery-orchestrator/SKILL.md); [review](https://github.com/jpantsjoha/ai-native-developer-experience/blob/e93069b92735ba096abf662f2b9d95a0ebfd36f9/skills/pr-reviewer/SKILL.md).

The alternative bare script path only seeds project operating files/checks and cannot be credited with model-driven task judgment by itself. A project profile must be activated by named humans before higher-risk operations; installing a user-scoped plugin does not approve a project. Maintainer-only `docs/MODEL-ROUTING.md` explicitly says its guidance is not automatic provider dispatch. This review does not assume unobserved host-install test or user adoption as a product-quality fact. [current status](https://github.com/jpantsjoha/ai-native-developer-experience/blob/e93069b92735ba096abf662f2b9d95a0ebfd36f9/docs/STATUS.md).

**Counterfactual owner test:** remove the host, keeping only the Python validators and manifest; no source-editing semantic agent runs. Restore a compatible installed host, native skill invocation and an authorized adopter project: the plugin-authored goal loop can drive semantic tool/test/review feedback via that host and produce an effectful deliverable. That is the supported S1 path. Remove adopter project-specific authority: risky operations become blocked, but the skill still exists for safe discovery/task planning. Independent ongoing viable S2-to-S5 management is not automatically created by this capability.

## Operational model

User-approved project goal → install and load first-party skill package and local profile → risk and authority check → `get-it-done` model-directed goal decomposition, source tools and test execution → fresh read-only reviewer verdict for exact candidate → permitted merge and recorded STATUS/CHANGELOG/issues (or leave blocked owner decisions in STATUS). Without a compatible host, model session or adopted project scope, it is not a standalone autonomous runtime. Documentation of future enterprise benefit is outside assessment evidence.
## S1 — Operations

## Self-hosted and non-human modes

The installed host is required for model-driven steps, with native tool permissions, model provider credentials and project repository context. Without the host the plugin ships scripts/templates. `seed` profile allows initial R0/R1 discovery work but not R2/R3 consequence. There is no continuously running fully agent-owned S2/S3/S4/S5.

## Recursion

Subskills such as pr-reviewer, delivery-orchestrator and model-enabled host subagents execute temporary phases of the single development goal. Role multiplication is not a proof of nested autonomous organizational recursions. External reviewer autonomy in task correctness is distinct from complementary audit of a whole managerial S3 system.

## Variety and escalation

Risk tiering, explicit human decisions, anti-self-review, bounded worktrees, tests and evidence receipts attenuate problems at the current task. Unexpected review findings can return for rework, and protected operations fail closed. No persistent organization-level algedonic return from viable lower units to upper management is evidenced.
