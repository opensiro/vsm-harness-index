## Purpose

Perform the first explicit semantic reassessment of the canonical Index after VSM Harness Profile v0.2.0 introduced the stricter separation:

```text
organizational function
→ decisive decision / feedback right
→ owner
→ supporting enforcement
→ closure
→ autonomy state
```

R1 also establishes explicit current Profile/procedure provenance for legacy canonical assessments without fabricating their original generation versions.

## Review strategy

R1 is **not** a wholesale re-proof of every existing statement.

For each harness:

1. inspect upstream changes since the accepted `review_ref` first;
2. identify whether those changes touch VSM-relevant architecture or evidence;
3. inspect the existing assessment for v0.2.0 semantic impact;
4. reopen only claims whose evidence or interpretation may be affected;
5. reuse still-valid pinned evidence rather than re-proving unchanged claims;
6. append one R1 event to `data/reassessment-history.psv` and update canonical freshness/current semantic provenance after a successful check.

A full deep review is required only when the upstream delta or semantic-impact test makes the existing evidence insufficient.

## Semantic impact priorities

Review in this order where possible:

1. positive S3 claims where deterministic budget, scheduler, concurrency, kill, routing, or controller mechanisms may have been mistaken for decision ownership;
2. positive S5 / `P` claims where human approval, escalation, prompts, or static policy may have been mistaken for identity/ultimate-policy closure;
3. positive S3* claims where autonomous audit judgment may have been conflated with deterministic verdict parsing/gating, or where independence is unclear;
4. S4 claims where sensing, memory, learning, planning, or self-improvement may lack a closed external-and-prospective adaptation path;
5. remaining canonical assessments, using a targeted v0.2.0 compatibility check rather than automatic full reassessment.

## Provenance rules

Every successful R1 check records:

```yaml
profile_version: 0.2.0
assessment_procedure_version: 0.2.1
last_checked_ref: <checked upstream ref>
last_checked_at: 2026-09-16
last_reassessment_round: R1
```

and the corresponding `data/reassessment-history.psv` event.

Generation provenance is separate:

```yaml
generated_profile_version: ...
generated_assessment_procedure_version: ...
```

If those fields already exist, preserve them unchanged. If a legacy assessment has no recorded generation provenance, **do not backfill or guess it** during R1. R1 establishes current accepted semantic provenance, not historical artifact origin.

## Outcomes

Use exactly one of:

- `no-upstream-change`
- `no-material-change`
- `reassessed-unchanged`
- `reassessed-changed`
- `same-ref-correction`
- `blocked`

`blocked` does not advance canonical freshness or current semantic provenance.
